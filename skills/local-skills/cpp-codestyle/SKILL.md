# C++ Code Style Guidelines for Workspace

Ты должен строго следовать следующим правилам форматирования и написания кода на C++ при генерации или изменении файлов:

## 0. Приоритет и запреты проекта

Полные правила проекта — в `SKILLS.md`; при расхождении они важнее этого файла. В частности:

* нет глобальных переменных и функций на уровне файла (в том числе `static`); `static constexpr` внутри класса-владельца — можно;
* нет исключений: `throw` в новом коде не появляется, ошибка возвращается результатом;
* нет своих `namespace` и `using namespace`: типы объявляются в глобальной области;
* делается только запрошенный функционал (MVP), без «на будущее».

Если задача требует нарушить запрет, сначала скажи об этом, а не обходи правило молча.

## 1. Именование (Naming Conventions)
* **Классы и структуры:** CamelCase с заглавной буквы (например, `class LineReader;`).
* **Функции и методы:** camelCase со строчной буквы (например, `void openFile();`).
* **Переменные:** snake_case в нижнем регистре (например, `int user_count;`).
* **Приватные члены классов:** snake_case с подчеркиванием на конце (например, `std::string internal_id_;`).
* **Константы:** Префикс `k` и CamelCase (например, `static constexpr int kMaxBufferSize = 1024;`). Константа живёт внутри класса-владельца; на уровне файла констант нет.

## 2. Форматирование (Formatting)
* **Отступы:** Используй ровно 4 пробела вместо табуляции.
* **Фигурные скобки:** Открывающая скобка `{` остается на той же строке, закрывающая `}` пишется с новой строки.
* **Длина строки:** Ограничивай код максимум 100 символами на строку.

## 3. Современный C++ (Modern C++ Practices)
* Всегда используй `nullptr` вместо `NULL` или `0`.
* Применяй `auto` только тогда, когда тип очевиден из правой части выражения (например, с `std::make_unique`).
* Явно указывай `override` для виртуальных функций в классах-наследниках.
* Предпочитай `std::unique_ptr` и `std::shared_ptr` сырым указателям (`*`). Для `QObject` допустимо владение через parent (`new QWidget(this)`), если так принято в проекте.

## 4. Инструменты проверки
* Перед завершением задачи убедись, что код соответствует правилам выше.
* Если в проекте есть `.clang-format`, отформатируй изменённые файлы: `clang-format -i <file>` из корня проекта.
* Если `.clang-format` нет, не добавляй свой конфиг и не переформатируй чужие строки — держи стиль вручную по правилам выше.
